# Process overview

## What I built

A synthwave endless-runner: drive a seeded, three-lane road until you crash, and your best distance for that day's seed becomes a permanent record in that day's archive. Other players who drove the same day appear afterwards as translucent ghost cars, a trace of a finished run, not a live opponent. Four weeks on top of that added real-time ghost broadcast, a leaderboard, coin-funded skins and trick ramps, and invite-only crews, each landing on top of a decision recorded as an ADR rather than a quiet change underneath it.

## Decisions, before code

The brief asked for a multi-user app on one 256MB Fly VM with a SQLite volume. Rather than accept whatever the agent reached for first, I ran three research passes comparing Node/Express, Astro, Django+Channels and Phoenix LiveView against those constraints before writing any code: Astro has no official WebSocket API, Phoenix's server-rendered diffing fights a client-side WebGL loop, and Django Channels has documented async-sync ORM issues at this size. Node won ([67140e1](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/67140e10a4230cd23243f24bc8a9e925be191f92)), and I left `scoreChanged()` as a no-op seam for the real-time work due two crits later. The same record keyed `best_runs` on `(user_id, track_seed)`, so a day became a permanent place rather than a rolling high score.

The workflow choice was just as deliberate. `plan.md` routes phases that mirror an existing pattern line-for-line (migrations, equip plumbing, running `pnpm check`) to smaller, cheaper subagents, and keeps phases needing visual or architectural judgement for a stronger one directing more closely ([3694834](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/36948343275a4422cbb559d4c1f90f48a4daacd4)). Cheap agents copy a reference well; they don't invent one.

## The moments that mattered

### Real-browser bugs no spec could reach - [9f280ff...9b681f8](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/compare/9f280ff49313711afcb2750ae8858dc784bf43ad...9b681f8e9d043ef9164239be9e546cffe8b68905)

Backend first: routes, WAL-mode SQLite, migrations run at container boot because Fly's `release_command` machines have no volume attached. Headless specs were green across the board. Rendering the actual game in a browser found two bugs no test reached: `.modal[hidden]` lost to the author's own `display: flex` on specificity, so the username modal stayed visibly frozen open even though the `hidden` attribute was toggling correctly in the DOM; and inverted triangle winding on the procedural road mesh pointed its front faces away from the camera, so Three.js culled the entire road. A mobile double-submit race showed up the same way, from actually touching the thing on a phone. None of the three could have been caught by an HTTP-only suite, because none of them touch an HTTP response.

### Three bugs hiding behind each other - [3eb77da](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/3eb77da3b804db9e2460b2248da310527111ad3c)

C9 asked for real-time ghosts, and the socket itself cost almost nothing: `scoreChanged()` was wired in C8 specifically as a no-op seam, so lighting it up didn't touch `runs.ts` at all. What actually consumed the week was verification. Two browser tabs failed to show propagation, and my first diagnosis was wrong: both tabs shared one cookie jar, so they were the same player. Driving two genuinely separate browsers uncovered three real bugs chained behind one another. `setAuthCookie` sets `httpOnly`, so `document.cookie` could never hold the token, so `hasAccount()` always returned false, so no real browser had ever actually saved a run, and every ghost in the database had been written by the test suite. Fixing that unmasked `requestAnimationFrame` reporting a timestamp earlier than the `lastTime` set when the frame loop finishes evaluating, which turned distance into `NaN`. A third bug, the day selector gating navigation on recorded runs instead of the calendar, had been sitting behind the first two the whole time. All three lived in `client/`, the one layer with no automated test of its own, and `pnpm test` stayed green through every one, because every HTTP spec sends the cookie by hand and none of them run a frame loop. The fix was a different sensor, not a new kind of test: a harness driving two real browsers with separate cookie jars, now written into CLAUDE.md as a standing rule.

### A decision that argued with itself twice - [a332385...f05a2a2](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/compare/a332385ba771b3d4efc829c39fa22e44d92186ce...f05a2a22cf3856d029a9d37c61665759d7201cd7)

This game refused leaderboards from the start, and argued it well: a ghost is a trace you drive past, not a rank you check. By Crit 10 that refusal was costing something real: most of a day's ghosts were never seen by anyone, because a run ends at the first barrier. I shipped a compromise, a distance-sorted roster with no rank numbers, to keep the claim alive while fixing the real problem. It didn't survive contact with itself: the record truncating that roster to ten rows had already admitted, arguing a different point, that "everyone reads the top of a distance-sorted list as furthest." That's the whole ranking, just without the number printed next to it. The next record said so directly, kept the panel, and printed the ranks, rewriting the project's own README rather than leaving a false sentence standing.

### Reversing "no following," in writing - [38b43d1](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/38b43d1935a18a738cb34d172c58849061196d01)

Crews ask for the same honesty. README said "no social layer, no following," and an invite-joined group that narrows your ghosts to crew-only is following in every sense that sentence meant to rule out. I rewrote the bullet in the same commit, and documented the disagreement it creates rather than hiding it: the road narrows to your crew, but the leaderboard panel stays switchable to the whole day. Coins stayed global on purpose: a two-person crew taking ranks one and two of its own leaderboard would mint coins for free.

### An invariant nobody was calling - [e6302a8](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/e6302a857f34ce220b6bac3faf8db04950f2d443)

`patternIsSolvable` was written specifically to prove the three-lane catalogue's one real promise, that a route through every pattern always exists, and then sat in the codebase for three weeks without being called from anywhere. The catalogue had been checked by hand once, at authoring time, and nothing was left to catch a future pattern that broke the guarantee. I wrote the missing test and wired both solvability functions into `spec/`, then added the lesson to CLAUDE.md directly: a guarantee is the test that runs, not the function that could.

### Two bugs fixed the same afternoon, after shipping - [a43a285](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/a43a285fa7bac57ea81873f81efb89c7e7a8cd66) / [344b58a](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/344b58a083a316f8c3a89b3884d07454febadca0)

Reviewing the run-end route before the final tranche, I noticed coin-credit and the best-run upsert committed as two separate writes, so a failure between them could credit coins for a run that never ended up recorded. I wrapped both in one `db.transaction()`. The same pass found a worse bug: a malformed percent-encoded cookie threw uncaught inside `tokenFromCookieHeader`. Over HTTP, Express turns that into a 500 for one request; over the raw `ws` handler on `/live`, nothing catches it, so one bad cookie could crash the process for every connected player. I wrote `spec/auth-cookie.test.ts` to pin both paths (a 401, an anonymous read, a socket that stays up) before fixing either.

### Six players against the real deploy - [f364f4f](https://github.com/comp4020-agentic-coding-studio/comp4020-final-marcuszorian/commit/f364f4fb355efc25b3ebeaa9b4418de142cac7e3)

Everything above was verified locally or against a single browser pair. For the multi-user requirement itself I wanted evidence from the actual deployment, so I pulled `flyctl logs` while six real people played at once, including two live `flyctl` restarts mid-session. Coin accounting and per-user high-score chains held up with no cross-user mixups, and the high-score sync fallback correctly restored state after both restarts. I reported what it didn't prove, too: ghost/live-position traffic isn't logged, so the real-time broadcast wasn't verified by this pass, and each restart opened a one-to-two-second window of proxy errors before the app finished binding its port.

### What's still unproven

Four weeks of lessons sat in ADRs and reflections before any became a rule the agent is actually held to: CLAUDE.md carried only the day-one ADR convention until this rewrite added the two rules above it. `client/src/` still has no WebGL unit suite of its own; the two-browser harness that found C9's bugs lives outside `pnpm check` as a tool I run rather than a sensor that runs itself. Audio, touch controls for tricks, and a presence indicator are all deliberately deferred, the last one refused twice in writing, on the same grounds the ghosts exist for in the first place.
